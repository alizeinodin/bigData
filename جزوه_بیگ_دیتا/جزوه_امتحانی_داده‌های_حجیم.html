Section 1 — Big Data, Data Mining and TF-IDF [S1]

Big Data
Definition: Datasetی که Volume، Velocity یا Variety آن از توان Toolهای معمول برای Processing در زمان معقول بیشتر است.
Purpose: برای مسئله‌هایی که به Distributed Storage و Parallel Processing نیاز دارند.
Execution: ابتدا Scale و نوع Data را تشخیص بده؛ سپس Framework مناسب مثل Hadoop را انتخاب کن.
Data Mining
Definition: فرایند کشف Pattern، Relation یا Knowledge مفید از Data.
Purpose: برای Description، Prediction، Classification، Clustering، Association و Outlier Detection.
Execution: Question را مشخص کن، Data را آماده کن، Algorithm را اجرا و Pattern را Evaluate کن.
TF (Term Frequency)
Definition: میزان تکرار Normalized یک Term در یک Document.
Purpose: نشان می‌دهد Term داخل همان Document چقدر برجسته است.
Execution: تعداد Term را بر بیشترین تکرار هر Term در همان Document تقسیم کن.
IDF (Inverse Document Frequency)
Definition: وزنی برای اندازه‌گیری نادر بودن Term در کل Document Collection.
Purpose: Termهای بسیار عمومی را کم‌اهمیت و Termهای کمیاب‌تر را پررنگ می‌کند.
Execution: نسبت N به تعداد Documentهای دارای Term را بگیر و log₂ آن را حساب کن.
TF-IDF
Definition: Product مقدار TF و IDF برای یک Term در یک Document.
Purpose: یافتن Termی که در یک Document زیاد ولی در کل Collection نادر است.
Execution: TF و IDF را جدا حساب کن و در هم ضرب کن.
Bonferroni Principle
Definition: وقتی تعداد Testها بسیار زیاد است، Event کم‌احتمال صرفاً بر اثر Chance بارها رخ می‌دهد.
Purpose: برای جلوگیری از اشتباه‌گرفتن False Positive با Pattern واقعی در Massive Data.
Execution: تعداد Eventهای تصادفی مورد انتظار را از احتمال هر Event × تعداد Trialها حساب و با یافته واقعی مقایسه کن.
Collaborative Filtering
Definition: Recommendation Methodی که از Rating/Behavior کاربران یا Itemهای مشابه استفاده می‌کند.
Purpose: پیشنهاد Movie، Product یا Content بدون نیاز به Feature محتوایی کامل.
Execution: User-based: Similar User پیدا کن؛ Item-based: Similar Item پیدا کن؛ سپس Score ناشناخته را Estimate کن.

TF-IDF به زبان ساده

کلمه مفید = در تعداد کمی سند، زیاد تکرار شده. کلماتی مثل «و» یا the که همه جا هستند، مفید نیستند (stop words).

TFᵢⱼ = fᵢⱼ / maxₖ(fₖⱼ)IDFᵢ = log₂(N / nᵢ)TF-IDF = TFᵢⱼ × IDFᵢ
مثال 1 — دقیقاً مثل سوال استاد (قدم‌به‌قدم)
فرض: تعداد کل اسناد N = 1024
کلمه w در 128 سند آمده (n = 128)
در سند j این کلمه 10 بار آمده
Frequentترین کلمه همان سند 100 بار آمده
گام 1) TF = 10 / 100 = 0.1 گام 2) IDF = log2(1024 / 128) = log2(8) = 3 چون 2^3 = 8 گام 3) TF-IDF = 0.1 × 3 = 0.3
پاسخ نهایی: 0.3
مثال 2 — برای فهم بهتر
اگر کلمه‌ای در همه سندها باشد: IDF = log2(1) = 0 → بی‌اهمیت.
کلمه «هادوپ» فقط در 1 سند از 3 سند آمده، 8 بار؛ max همان سند = 20:
TF = 8/20 = 0.4 IDF = log2(3/1) ≈ 1.58 TF-IDF ≈ 0.4 × 1.58 = 0.63
پاسخ نهایی: ≈ 0.63

Collaborative Filtering

  • User-based: کاربران شبیه تو چه چیزهایی را پسندیده‌اند؟ همان‌ها را به تو پیشنهاد بده.
  • Item-based: آیتم‌های شبیه آنچه پسندیده‌ای را پیشنهاد بده.

در درس به Recommendation Engine (مثل Netflix و Amazon) و Behavioral Data اشاره شده.

Section 2 — Cluster Computing, RDBMS and Hadoop [S2]

RDBMS
Definition: Database Management System مبتنی بر Relation/Table، Schema و Transactionهای ACID.
Purpose: برای Structured Data، Query پیچیده و Transaction دقیق.
Execution: Data را در Table ذخیره کن و با SQL و Key/Constraint مدیریت کن.
Cluster Computing
Definition: اجرای یک Workload روی چند Node متصل که به‌صورت یک System همکاری می‌کنند.
Purpose: برای Horizontal Scaling، Parallel Processing، High Availability و Fault Tolerance.
Execution: Data و Task را بین Nodeها Partition کن، Load را Balance و Failure را Recover کن.
Hadoop
Definition: Framework متن‌باز برای Distributed Storage و Batch Processing روی Commodity Hardware.
Purpose: برای Fileهای بسیار بزرگ و Jobهای Sequential/Batch با Fault Tolerance.
Execution: Data را در HDFS ذخیره و Computation را با MapReduce نزدیک Data اجرا کن.
HDFS
Definition: Distributed File System که File را به Block تقسیم و روی چند DataNode Replicate می‌کند.
Purpose: Storage مقیاس‌پذیر و مقاوم به Failure برای Fileهای بزرگ.
Execution: NameNode Metadata را نگه می‌دارد؛ DataNodeها Blockها را ذخیره می‌کنند.

محدودیت‌های RDBMS: Scalability گران، سرعت، Fault Tolerance، پردازش پیشرفته روی ترابایت/پتابایت.

ویژگی‌های Cluster (حفظ کن): High Availability، Fault Tolerance، Data Replication، Load Balancing، Automated Failover، Backup & Recovery، Monitoring، Scalability افقی.

Section 3 — MapReduce [S3]

MapReduce
Definition: Distributed Programming Model برای تبدیل Input به Key–Value Pair و Aggregate کردن Valueهای هم‌Key.
Purpose: برای Batch Processing موازی روی Data حجیم با Fault Recovery خودکار.
Execution: ۱) Map بنویس ۲) System، Shuffle/Sort/Partition را انجام می‌دهد ۳) Reduce بنویس.
Map
Definition: تابعی که هر Input Record را به صفر، یک یا چند (key,value) تبدیل می‌کند.
Purpose: استخراج Key و Intermediate Value به‌صورت Parallel.
Execution: هر Mapper یک Chunk مستقل را می‌خواند و emit می‌کند.
Shuffle
Definition: مرحله System برای انتقال، Sort و Group کردن همه Valueهای دارای Key یکسان.
Purpose: تضمین می‌کند Reduce همه Valueهای یک Key را یک‌جا ببیند.
Execution: Partitioner مقصد را تعیین می‌کند و System داده‌های میانی را روی Network جابه‌جا می‌کند.
Reduce
Definition: تابعی که یک Key و List همه Valueهای آن را به Output نهایی تبدیل می‌کند.
Purpose: Aggregation، Join، Count، Sum یا ساخت نتیجه نهایی.
Execution: برای هر Key دقیقاً روی Group متناظر اجرا می‌شود.
Combiner
Definition: Optional Local Reduce در سمت Mapper.
Purpose: کاهش حجم Intermediate Data روی Network.
Execution: فقط وقتی Operation، Associative و Commutative است اجرا کن؛ جای Reduce نهایی نیست.

تو فقط دو تابع می‌نویسی؛ سیستم بقیه کار را می‌کند.

  1. Map: هر تکه ورودی را بخوان و جفت‌های (کلید، مقدار) بساز.
  2. Shuffle: همه مقدارهایی که کلید یکسان دارند را در یک لیست بگذار.
  3. Reduce: برای هر کلید، لیست مقدارها را ترکیب کن (جمع، شمارش، ...).
Map: input → (key, value)Shuffle: (k,v1), (k,v2), ... → (k, [v1, v2, ...])Reduce: (k, [v1, v2, ...]) → (k, result)
مثال خیلی ساده — شمارش کلمه
دو جمله داریم: «big data» و «big data systems»
Map از جمله 1: (big,1) (data,1) Map از جمله 2: (big,1) (data,1) (systems,1) بعد از Shuffle: big → [1, 1] data → [1, 1] systems → [1] Reduce (جمع): big = 2 data = 2 systems = 1
پاسخ نهایی: big=2 ، data=2 ، systems=1

Combiner: اگر عمل Reduce جابجایی‌پذیر و انجمنی باشد (مثل جمع)، می‌توان قبل از شبکه یک Reduce محلی زد تا ترافیک کم شود.

اگر این خراب شودچه کار می‌کنند؟
Masterمعمولاً کل Job از نو شروع می‌شود
Map Workerهمان Mapها روی نود سالم دوباره اجرا می‌شوند
Reduce WorkerReduce دوباره اجرا می‌شود

Workflow Systems: به‌جای فقط Map→Reduce، یک گراف DAG از توابع (Clustera، Hyracks).

Pregel: سیستم محاسبات گرافی با SuperStep و Checkpoint برای Fault Tolerance در Algorithms بازگشتی.

Matrix–Vector Multiplication
Definition: Operationی که Dot Product هر Row Matrix M با Vector V را در uᵢ قرار می‌دهد.
Purpose: هسته بسیاری از Graph/ML Algorithmها مانند PageRank.
Execution: Mapper مقدار mᵢⱼ×vⱼ را با Key=i می‌سازد و Reducer تمام Partial Productهای Row i را Sum می‌کند.
Matrix–Matrix Multiplication
Definition: Operationی که pᵢₖ را از Dot Product سطر i Matrix اول و ستون k Matrix دوم می‌سازد.
Purpose: اجرای Linear Algebra بزرگ‌تر از RAM.

Matrix و Vector:

تکمله B — اجرای داخلی و توسعه‌های MapReduce [D2]

Map Task، Partitioning و Grouping

  • عنصر ورودی (تاپل/سند) نباید بین دو chunk نصف شود.
  • Map می‌تواند برای یک ورودی صفر، یک یا چند زوج و حتی چند کلید یکسان تولید کند.
  • اگر r Reducer باشد، h(k) یکی از 0 تا r−1 را انتخاب می‌کند.
  • هر Map برای هر Reduce یک فایل محلی میانی دارد؛ بنابراین r فایل می‌سازد.
  • شرط اصلی: کلیدهای یکسان حتماً به یک Reduce بروند؛ کلیدهای متفاوت می‌توانند هم‌مقصد شوند.
k₁ = k₂ ⇒ h(k₁) = h(k₂)(k,v₁),(k,v₂),… ⇒ (k,[v₁,v₂,…])

Grouping سیستمی را با GROUP BY رابطه‌ای اشتباه نکن: Grouping فقط مقادیر هم‌کلید را کنار هم قرار می‌دهد؛ Aggregation عملی است که کاربر در Reduce می‌نویسد.

Combiner — دام مهم امتحانی

(a ∘ b) ∘ c = a ∘ (b ∘ c) (Associative)a ∘ b = b ∘ a (Commutative)

Combiner جای Reduce نهایی را نمی‌گیرد؛ فقط تکراری‌ها/مقادیر همان Map را ترکیب می‌کند. مثلاً در Projection تکراری‌های دو Map مختلف فقط در Reduce نهایی حذف می‌شوند.

Join: اگر برای یک کلید، ۲ تاپل R و ۳ تاپل S باشد، Reduce باید ۲×۳=۶ خروجی بسازد.

Matrix×Vector وقتی Vector در RAM جا نمی‌شود

Matrix را به نوارهای عمودی و Vector را به قطعات افقی متناظر تقسیم کن؛ تعداد نوارها طوری باشد که قطعه Vector و chunk Matrix در حافظه یک نود جا شود. هر Map سهم جزئی uᵢ را می‌سازد و Reduce سهم نوارهای مختلف را روی i جمع می‌کند.

Matrix×Matrix: دو Job در برابر یک Job

دو Job: Job1 روی j جوین و ((i,k),mᵢⱼnⱼₖ) تولید می‌کند؛ Job2 روی (i,k) جمع می‌زند.

یک Job: هر mᵢⱼ برای تمام kها و هر nⱼₖ برای تمام iها تکثیر می‌شود. Job کمتر، ولی Replication و ترافیک بیشتر.

Transitive Closure (Transitive Closure)

P = E ∪ { (x,y) | ∃z : P(x,z) ∧ P(z,y) }

اگر مسیر (1,2) و (2,3) داشته باشیم، Join روی گره میانی 2 مسیر (1,3) را می‌سازد. دو نوع Task: Join Task و Duplicate-Elimination Task. مسیر جدید پس از Duplicate Elimination به Join Taskهای مربوط به دو سر مسیر فرستاده می‌شود؛ توقف وقتی مسیر جدیدی ساخته نشود.

Pregel

  • اجرای همگام در مرحله‌های SuperStep
  • Checkpoint = کپی وضعیت همه Taskها
  • در خرابی، بازگشت به آخرین Checkpoint
  • زمان ترمیم باید خیلی کمتر از میانگین زمان بین دو خرابی باشد

Communication Cost، Reducer Size و Replication Rate

Communication Cost = Σ_task |Input_task|ρ = (# Map outputs) / (# input elements)

Reducer Size (q): بیشترین تعداد مقدار مجاز برای یک Reduce. q کوچک‌تر → Reduceهای بیشتر و موازی‌سازی بیشتر؛ اگر ورودی Reduce در RAM جا شود I/O کمتر می‌شود.

Trade-off: یک Reduce هزینه انتقال حداقل ولی زمان اجرا زیاد؛ Reduceهای بیشتر زمان کمتر ولی احتمال تکثیر/هزینه بیشتر.

Pr[ hπ(C₁) = hπ(C₂) ] = J(C₁, C₂)
مثال

امضا را به چند نوار (band) تقسیم کن. اگر دو سند حتی در یک نوار کاملاً یکسان بودند، آن‌ها را candidate حساب کن و بعد دقیق چک کن.

P = 1 − (1 − sʳ)ᵇ
که در آن:

b = تعداد bandها

یعنی حدود 99.97٪ احتمال دارد جفت واقعاً مشابه را پیدا کنیم.

Section 8 — Apriori, Closed Itemset, Maximal Itemset and CHARM [S8]

Support
Definition: Fraction Transactionsی که یک Itemset یا Rule را پوشش می‌دهند.
Purpose: اندازه‌گیری فراگیری Pattern در کل Database.
Execution: Support Count را بر تعداد کل Transactionها تقسیم کن.
Confidence
Definition: Conditional Probability رخداد Consequent وقتی Antecedent رخ داده است.
Purpose: اندازه‌گیری Reliability یک Association Rule.
Execution: Support(A∪B) را بر Support(A) تقسیم کن.
Apriori
Definition: Level-wise Frequent Itemset Algorithm مبتنی بر Downward-closure Property.
Purpose: کشف Itemsetهای Frequent و ساخت Association Rule.
Execution: از L₁ شروع کن؛ Candidate Cₖ را Join، با زیرمجموعه‌های Infrequent Prune و Support را Count کن.
Closed Itemset
Definition: Frequent Itemsetی که Superset هم‌Support ندارد.
Purpose: فشرده‌سازی Lossless Frequent Patternها همراه با حفظ Support.
Execution: Supersetها را بررسی کن یا Closure را با Tidset به‌دست آور.
Maximal Itemset
Definition: Frequent Itemsetی که هیچ Superset Frequent ندارد.
Purpose: فشرده‌سازی قوی‌تر مرز Frequentها، بدون حفظ Support دقیق زیرمجموعه‌ها.
Execution: بررسی کن هیچ Extension آن Support≥minsup نداشته باشد.
CHARM
Definition: Vertical Closed-itemset Mining Algorithm مبتنی بر Tidset Intersection.
Purpose: استخراج مستقیم Closed Itemset بدون تولید همه Frequent Itemsetها.
Execution: Itemsetهای هم‌Prefix را ترکیب، Tidsetها را Intersect و با Equality/Subset Relation هرس کن.
support(X) = support_count(X) / |D|support(A ⇒ B) = support(A ∪ B)confidence(A ⇒ B) = support(A ∪ B) / support(A)M ⊆ C ⊆ F

از 100 سبد خرید: نان در 40 سبد، نان+شیر در 30 سبد.
قانون: نان ⇒ شیر support = 30/100 = 0.3 confidence = 30/40 = 0.75 = 75%

پاسخ نهایی: conf = 75%

Section 9 — Clustering [S9]

Clustering
Definition: Unsupervised Learning برای تقسیم Objectها به Clusterهایی با Intra-cluster Similarity زیاد و Inter-cluster Similarity کم.
Purpose: کشف Structure پنهان وقتی Label از قبل وجود ندارد.
Execution: Representation، Similarity/Distance، Algorithm Family و Stop Criterion را انتخاب و نتیجه را Evaluate کن.
K-Means
Definition: Partitioning Algorithm که هر Cluster را با Centroid/Mean نمایش می‌دهد.
Purpose: Numeric Data، Clusterهای Spherical و اجرای سریع.
Execution: k Centroid اولیه → Assignment به نزدیک‌ترین Centroid → Update Mean → Repeat تا Convergence.
DBSCAN
Definition: Density-based Clustering با دو Parameter به نام Eps و MinPts.
Purpose: کشف Shape دلخواه، Core/Border Point و Noise بدون تعیین k.
Execution: از یک Core شروع کن و همه Pointهای Density-reachable را Expand کن.
BFR
Definition: Scalable Clustering Algorithm برای Data عظیم با Summaryهای N، SUM و SUMSQ.
Purpose: وقتی Data در RAM جا نمی‌شود و Clusterها تقریباً Gaussian و axis-aligned هستند.
Execution: Chunkها را بخوان؛ Pointها را بین DS/CS/RS قرار بده و Summaryها را Update/Merge کن.
CURE
Definition: Hierarchical Clustering با چند Representative Point Shrink‌شده برای هر Cluster.
Purpose: Clusterهای Non-spherical و مقاومت بهتر در برابر Outlier.
Execution: Sample → Hierarchical Clustering → انتخاب Representativeهای دور → Shrink → Merge/Assign.
OPTICS
Definition: Ordering Algorithm مبتنی بر Density که Reachability Structure را تولید می‌کند.
Purpose: Datasetهایی که Clusterهای با Density متفاوت دارند.
Execution: Core Distance و Reachability Distance را حساب و Pointها را به ترتیب Priority پردازش کن.

هدف: اعضای یک Cluster به هم نزدیک؛ Clusters مختلف از هم دور. Unsupervised Learning (برخلاف Classification).

انواع: Partitioning (K-Means، K-Medoids، PAM، CLARA، CLARANS) · Hierarchical (AGNES، DIANA) · Density (DBSCAN، OPTICS، DENCLUE) · Grid (STING، CLIQUE)

Centroid در برابر Clustroid

Centroid مناسب فضای اقلیدسی و ممکن است عضو واقعی داده نباشد. در اسناد/رشته‌ها «میانگین» معنی ندارد، پس clustroid یا medoid می‌گیریم.

Linkage، Radius و Diameter

Single(C₁,C₂) = min d(x,y)Complete(C₁,C₂) = max d(x,y)Average(C₁,C₂) = [Σ d(x,y)] / (|C₁||C₂|)radius(C) = max d(x, μC)diameter(C) = max d(x,y)
  • Single: مناسب شکل زنجیره‌ای، ولی اثر chaining و پل Noiseی دارد.
  • Complete: Cluster فشرده، ولی حساس به outlier.
  • Average: تعادل بین دو روش.

توقف: رسیدن به k، عبور radius/diameter از آستانه، افت Density، جهش کیفیت یا یک Cluster.

K-Means — نکات امتحانی

SSE = Σⱼ Σₓ∈Cⱼ ||x − μⱼ||²
  • هر مرحله SSE را زیاد نمی‌کند، پس همگرا می‌شود؛ اما به بهینه محلی.
  • مقداردهی بهتر: مراکز دور ازهم، نمونه کوچک، یا چند اجرا و انتخاب کمترین SSE.
  • انتخاب k: Elbow؛ جایی که افزایش k دیگر بهبود زیاد نمی‌دهد.
  • ضعف: نیاز به k، حساس به init/outlier، نامناسب شکل غیرکروی و Nominal Attribute.

K-Medoids، PAM، CLARA، CLARANS

  • K-Medoids: نماینده نقطه واقعی؛ Distance دلخواه؛ مقاوم‌تر ولی گران‌تر.
  • PAM: k medoid → تخصیص → امتحان تعویض medoid/non-medoid → قبول اگر هزینه کم شد.
  • CLARA: چند نمونه تصادفی، PAM روی هر نمونه، ارزیابی روی کل داده؛ سریع ولی وابسته به نمونه.
  • CLARANS: جواب‌های medoid را گراف می‌بیند و همسایه تصادفی را می‌گردد؛ کیفیت بهتر، هنوز پرهزینه.

BFR — فرض‌ها و سه مجموعه

فضای اقلیدسی پُربعد؛ Cluster تقریباً نرمال؛ ابعاد مستقل؛ بیضی‌ها محورهم‌راستا. هر Cluster با 2d+1 مقدار N، SUM، SUMSQ خلاصه می‌شود.

مجموعهمعنی
DS (Discard Set)با اطمینان عضو Cluster اصلی؛ خود نقاط دور ریخته و خلاصه حفظ می‌شود
CS (Compression Set)گروه فشرده، ولی هنوز نزدیک هیچ DS نیست
RS (Retained Set)نقاط منفرد/مشکوک که صریح نگه داشته می‌شوند
Mahalanobis(x,C) = √ Σᵢ [ (xᵢ − μᵢ) / σᵢ ]²

مراحل: نمونه اولیه و DS → RS → Cluster‌کردن RS و ساخت CS → خواندن chunk → نزدیک‌ها به DS، سپس CS، بقیه RS → ادغام CSها → در chunk آخر ادغام مناسب با DS.

CURE

  1. نمونه تصادفی در RAM
  2. Hierarchical Clustering نمونه
  3. انتخاب c نماینده که از هم دور باشند
  4. حرکت هر نماینده کسری α به سمت centroid
  5. Distance Clusters = کمترین Distance نماینده‌ها
  6. تخصیص کل داده به نزدیک‌ترین نماینده
r′ = r + α(μ − r)

نماینده‌های متعدد شکل Cluster را می‌گیرند؛ shrink به مرکز اثر outlier مرزی را کم می‌کند.

DBSCAN — روابط دقیق

N₍Eps₎(q) = { p | dist(p,q) ≤ Eps }Core ⇔ |N₍Eps₎(q)| ≥ MinPts
  • Directly density-reachable: p در همسایگی q و q یک Core باشد؛ لزوماً متقارن نیست.
  • Density-reachable: زنجیره‌ای از دسترسی‌های مستقیم.
  • Density-connected: نقطه o وجود دارد که p و q هر دو از آن قابل‌دسترسی‌اند؛ متقارن است.
  • با index فضایی تقریباً O(n log n)، بدون آن O(n²).
  • Eps کوچک → noise زیاد؛ Eps بزرگ → اتصال Clusters جدا.
  • MinPts کم → Noise Cluster؛ MinPts زیاد → Cluster کوچک حذف.

OPTICS

coreDist(p) = distance to the MinPts-th nearest neighborreachDist(p,q) = max(coreDist(q), dist(p,q))

به‌جای یک افراز، ترتیب نقاط و Reachability Plot می‌دهد. دره‌ها Cluster‌اند؛ دره عمیق‌تر یعنی Density بیشتر. مناسب‌تر از DBSCAN برای Density‌های متفاوت.
